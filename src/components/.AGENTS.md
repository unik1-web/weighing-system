# Каталог: src/components/

## Назначение
Компоненты пользовательского интерфейса: форма взвешивания, панель автосъёма и экраны настроек.

## Файлы

### WeighingForm.tsx
- Компонент `WeighingForm`:
  - фиксирует вес через `ScalePanel` и ручной ввод;
  - по `SITE_RUNTIME_CHANGED_EVENT` пересчитывает активный scale context;
  - новые create/update операций талонов пишут `site_id`, `scale_id`, `scale_role`, `scale_device` из текущего активного комплекта;
  - после persist вызывает `captureAfterWeightPersist` из `photo-capture` (single: gross+tare; dual-first/complete: фаза шага);
  - soft `photoWarning` при degrade / ticket_not_found / rotation (не modal hard-fail);
  - показывает `<TicketPhotosPreview>` для `lastTicket`;
  - при complete patch **не** содержит `photo_*` — stubs сохраняются через `TicketStorage.update`;
  - поддерживает поле `manual_weight_reason`;
  - применяет валидацию обязательности причины только к весам текущего шага;
  - при dual completion не очищает существующую причину без явного действия оператора;
  - пишет runtime-логи блокировки нестабильной фиксации, отказа `manual_weight_reason` и сохранения источников `manual/instrument`.

### VideoSettingsSection.tsx
- Компонент `VideoSettingsSection` (admin):
  - читает `GET /api/cameras/capability`;
  - при `available=false` показывает «недоступно в этой сборке», без CRUD/toggle;
  - при `available=true`: переключатель `video_enabled`, timeout/quality → `SettingsStorage` (INI);
  - CRUD до 4 камер (`CameraStorage` → sync), ROI для overview, «Проверить» → `postCameraTest`;
  - кнопки «Снять эталон primary/spare» → `captureEtalonAndFlush` (merge в `CameraStorage` до flush) + превью;
  - URL с паролем: masked placeholder, dirty-флаг не затирает secret;
  - удаление камеры не чистит `ticket_photos` на клиенте.

### TicketPhotosPreview.tsx
- Компонент `TicketPhotosPreview`:
  - active: читает `TicketPhotoStorage.getByTicket` (или явный `photos`);
  - фильтр `status=success` + `file_path`; группировка по `gross`/`tare` (все роли, включая overview);
  - клик → `PhotoLightbox`; `img onError` → «Файл недоступен» и уменьшение счётчика;
  - пусто → «Нет снимков».

### PhotoLightbox.tsx
- Компонент `PhotoLightbox`:
  - полноэкранный просмотр JPEG; закрытие по backdrop / кнопке «Закрыть».

### ScalePanel.tsx
- Компонент `ScalePanel`:
  - подключает runtime для активного комплекта;
  - показывает источник чтения (`Browser Web Serial` / `Backend API`) и runtime-статус;
  - отображает предупреждения для нестабильного веса по матрице `stable_mode`;
  - обрабатывает режим `manual_only` и явный action `Повторить подключение`;
  - сообщает родителю о блокировке захвата нестабильного веса через `onUnstableBlocked`.

### SiteScalesSettingsSection.tsx
- Компонент `SiteScalesSettingsSection`:
  - редактирует draft-конфигурации `primary` и `spare`;
  - сохраняет `adapter_id` и `connection_json`;
  - блокирует сохранение при compile/preview ошибках `generic-regex`;
  - показывает статус `pending_runtime` для конфигураций без `test_frame`;
  - отображает active set, `adapter_id`, `transport` и статус подключения после switch;
  - пишет runtime-логи успешного сохранения конфигурации, невалидного draft и переключения `primary/spare`.

### ScaleSetSwitchWizard.tsx
- Компонент `ScaleSetSwitchWizard`:
  - выполняет switch через `applyScaleSetSwitch()`;
  - показывает явное сообщение при no-op (уже активный комплект);
  - предупреждает о переходе в `manual_only` для комплекта без рабочей конфигурации;
  - при переходе на spare: если есть enabled-камеры с `etalon_spare_path`, `video_enabled` и capability — блок сверки эталон (`/api/photos/…`) vs live через `postCameraSnapshot` (не `postCameraTest`);
  - live fail → эталон + предупреждение + чекбокс «Принял без live-сверки» (не hard-fail);
  - без эталонов / video off / capability false — текстовый чеклист как раньше;
  - primary — без расширенной сверки;
  - хелперы: `selectEnabledSpareEtalonCameras`, `shouldShowSpareEtalonComparison`, `fetchSpareLiveSnapshots`, панель `SpareEtalonComparisonPanel`.

### ScaleConnectionFields.tsx
- Компонент `ScaleConnectionFields`:
  - рендерит transport/parser-поля в зависимости от `adapter_id` и `transport`;
  - для `generic-regex` поддерживает `pattern`, `flags`, `weight_group`, `stability_group`, `stable_values`, `unstable_values`, `unit_group`, `test_frame`;
  - отображает результат preview-валидации до сохранения.

### SettingsView.tsx
- Компонент `SettingsView`:
  - содержит глобальные настройки приложения;
  - включает `manual_weight_reason_policy`;
  - отображает ошибки draft-конфигураций секции комплектов;
  - встраивает `VideoSettingsSection` рядом с `SiteScalesSettingsSection`;
  - общий Save не затирает `video_enabled` / timeout / quality (их пишет секция видео).

### ArchiveView.tsx
- Компонент `ArchiveView`:
  - загружает архивные годы через `GET /api/archive/years` отдельным запросом;
  - не открывает журнал до явного выбора года;
  - читает журнал и карточку выбранного года через stage-6 archive API;
  - показывает mixed legacy warning без смены выбранного года;
  - не использует `TicketStorage` и не меняет active-year journal state;
  - рендерит control редактирования только при `isAdmin`;
  - после успешного PATCH обновляет карточку и строку журнала выбранного архива.

### ArchiveTicketCard.tsx
- Компонент `ArchiveTicketCard`:
  - readonly-карточка архивного тикета (`year`, номер, дата/время, статус, `auto_closed`, `reo_status`, реквизиты);
  - показывает ticket-level mixed legacy warning;
  - печатает completed ticket через `printTicket(..., { source: 'archive' })` без записи в active storage;
  - при наличии stubs `photo_*` показывает `<img src="/api/photos/...">` через `mapArchiveStubPreviews` (overview / полный `ticket_photos` в archive не добавляются).

### ArchiveTicketEditDialog.tsx
- Компонент `ArchiveTicketEditDialog`:
  - admin-only форма PATCH только по whitelist UC-05 (русские подписи полей);
  - для `reo_status = sent` показывает предупреждение и требует явного подтверждения;
  - обрабатывает `archive_reo_ack_required` / `archive_edit_forbidden_field` / `archive_edit_validation_failed`;
  - после успеха отдаёт ответ в `ArchiveView` для обновления карточки и журнала.

### YearRotationDialog.tsx
- Компонент `YearRotationDialog`:
  - показывает preview ротации (`source_year`, `target_year`, `open_candidates`, `blocking_tickets`, `pending_reo_count`);
  - блокирует confirm при наличии blocking-тикетов;
  - требует явного подтверждения при `pending_reo_count > 0`;
  - используется вместе с logout flow после успешного commit.

### WeighingJournal.tsx
- Компонент `WeighingJournal`:
  - остаётся журналом только активного года;
  - архивный режим подключается отдельным `ArchiveView`, без встраивания архивной карточки в этот компонент.
  - отображает ошибку write-gate при событии `ACTIVE_WRITE_BLOCKED_EVENT`.
  - в модалке деталей рендерит `<TicketPhotosPreview ticketId=... />`.

### PrintAct.tsx
- `printTicket(ticket, settings?, options?)`:
  - общий шаблон печати для active и archive;
  - `options.source = 'archive'` гарантирует отсутствие side-effect записи в active storage / REO reset.

### VescomImportView.tsx / MetraImportView.tsx / WaImportView.tsx
- Компоненты импорта данных:
  - реагируют на `ACTIVE_WRITE_BLOCKED_EVENT`;
  - показывают пользователю ошибку `rotation_in_progress`, что импорт недоступен до завершения смены года.

## Зависимости
- `src/lib/site.ts` — доменные операции площадки и комплектов.
- `src/hooks/useScale.ts` — runtime-хук автосъёма.
- `src/lib/storage.ts` — сохранение настроек и талонов.
- `src/hooks/useYearRotation.ts` — orchestration ротации года.
