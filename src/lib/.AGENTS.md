# Каталог: src/lib/

## Назначение
Доменная и инфраструктурная логика frontend: storage, runtime-клиенты, API-обёртки и вспомогательные правила.

## Файлы

### scale-runtime-client.ts
- Класс `ScaleRuntimeClient`:
  - `connect(activeScale)` — выбирает `web_serial` или `backend_api`;
  - `read(timeoutMs)` — читает через `ScaleConnection` (Web Serial) или `/api/scales/read`;
  - `getStatus()` — текущее состояние runtime;
  - `disconnect()` — завершает runtime-сессию;
  - нормализует runtime-ошибки в коды `invalid_connection_config`, `unsupported_transport`, `transport_unavailable`, `read_timeout`, `stale_session`, `backend_unavailable`;
  - выполняет не более одной автоматической retry-попытки, затем переводит форму в `manual_only`;
  - обработка `SITE_RUNTIME_CHANGED_EVENT` — закрывает backend session и переводит state в `disconnected`.
  - structured logging событий `connect/read/manual_only/retry` через `logger.scaleRuntime`.

### logger.ts
- Frontend logger:
  - хранит structured `runtime_context` (`site_id`, `scale_id`, `scale_role`, `adapter_id`, `transport`, `session_id`, `code`, `phase`);
  - применяет redaction для `COM/TTY/IP` и секретов URL (userinfo password, query `password`/`pass`/`token`/`key`) в details/context;
  - подавляет повтор одинаковых runtime errors (debounce) и пишет агрегированный счётчик;
  - клиентские события камер (`cameras`): `ticket_not_found` / merge fail без серверной детализации URL.

### site.ts
- Доменные функции площадки/комплектов:
  - `ensureDefaultSiteAndScales(settings)` — idempotent-инициализация и legacy-миграция `scale_device_id` в `scales.connection`;
  - `updateScaleConfiguration(scaleId, input, syncMirror)` — сохранение `adapter_id` и `connection`;
  - `ticketScaleFieldsFromRuntime()` — snapshot полей для новых талонов.

### storage.ts
- Локальные фасады хранения:
  - `SettingsStorage`, `ScaleStorage`, `SiteRuntimeStorage`, `TicketStorage`.
  - stage-6 расширения моделей: `WeighingTicket.auto_closed`, `TicketAuditEvent.event_type/source_year/changed_fields/old_values/new_values/reo_divergence_warning`, `AppSettings.active_year`.
  - stage-7 video settings в `AppSettings`: `video_enabled` (default false), `camera_capture_timeout_sec` (3), `camera_jpeg_quality` (80) — SoT через config.ini / SettingsStorage.
  - `CameraStorage` (`app_cameras`): `getAll`, `getBySite`, `replaceAll`, `upsert`, `remove`.
  - `TicketPhotoStorage` (`app_ticket_photos`): `getAll`, `getByTicket`, `upsertMany` (без replaceAll целой коллекции из ответа capture).
  - `upsertTicketPhotosFromCapture(fullList, captureTicketPhotos)` — merge по `id` или UNIQUE `(ticket_id, camera_id, event)`.
  - `WeighingTicket.year` (readonly) для различения одинаковых номеров талонов по годам.
  - `WeighingTicket.capture_token` — транзиентный маркер post-capture flush (не колонка БД).
  - `TicketStorage.update` не нормализует отсутствующие `photo_*` в null (preserve stubs).
  - normalizer аудита поддерживает одновременно legacy `action` и stage-6 `event_type`.
  - `TicketStorage` фильтрует журнал и нумерацию по `active_year`, чтобы не смешивать active/archive записи.
  - Нормализация legacy-конфигов: `adapter_id='web_serial'` + `connection.device_id` → канонический built-in `adapter_id`.

- Реэкспорт оркестрации из `photo-capture.ts` и API-клиентов capability/snapshot/test/etalon/capture.

### photo-capture.ts
- Оркестрация UC-03 после persist веса:
  - `captureAfterWeightPersist(ticketId, event)` → `{ capture, warning }`: flush → `POST /api/cameras/capture` → `applyCaptureMergeToStorage` → flush;
  - `mergeTicketPhotoStubsFromCapture` — null stubs только при непустом `capture_token`; noop preserve;
  - `applyCaptureMergeToStorage` — upsert `ticket_photos` (без replaceAll) + `capture_token` на тикете;
  - `summarizeCaptureResults` — soft toast «Снято N из M» / «снимки недоступны»;
  - 404 `ticket_not_found` / 409 `rotation_in_progress` / merge fail → warning + клиентский лог (`cameras`), вес не откатывается.

### api.ts
- API-обёртки:
  - базовые `apiGet/apiPost/apiPatch`.
  - stage-6 контракты: `getArchiveYears`, `getArchiveTickets`, `getArchiveTicket`, `patchArchiveTicket`, `getYearRotationPreview`, `commitYearRotation`;
  - stage-7 camera API: `fetchCameraCapability`, `postCameraSnapshot`, `postCameraTest`, `postCameraEtalon`, `postCameraCapture`; типы `CameraCapabilityResponse`, `CameraCaptureResponse`.
  - `ArchiveTicketDetails` допускает optional `photo_entry_path` / `photo_exit_path` (archive stubs).
  - коды ошибок archive-edit: `archive_edit_forbidden_field`, `archive_edit_validation_failed`, `archive_reo_ack_required`; warning `archive_reo_sent_warning`.
  - типы archive-read: `ArchiveYearInfo`, `ArchiveTicketSummary`, `ArchiveTicketDetails`, `ArchiveWarning`.
  - типизированная ошибка `ApiRequestError` с полями `code/status` для stage-6 кодов (`rotation_in_progress`, `invalid_archive_year`, `archive_year_not_found`, `archive_open_failed`, ...).

### storage-sync.ts
- Синхронизация frontend storage:
  - `pauseDatabaseSync()` / `resumeDatabaseSync()`.
  - stage-6 extension points: `beginRotationCommitSyncPause()` / `endRotationCommitSyncPause()`.
  - обработка кодов `rotation_in_progress`, `invalid_archive_year`, `archive_year_not_found` в ответах API.
  - событие `ACTIVE_WRITE_BLOCKED_EVENT` для UI-ошибки write-gate во время ротации.
  - защита от перезаписи `localStorage`: при ошибке bootstrap миграции из `GET /api/config` данные клиента не затираются.

### weighing-mode.ts
- Pure-хелперы режима взвешивания:
  - `isManualWeightUsedOnCurrentStep(...)` — определяет, есть ли ручной источник среди весов текущего шага;
  - `isManualWeightReasonRequiredOnCurrentStep(...)` — проверяет обязательность причины по policy и текущим слотам.
