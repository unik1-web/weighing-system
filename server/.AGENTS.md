# Каталог: server/

## Назначение
Backend Flask API, persistence-слой и контрактные модули runtime-адаптеров весов.

## Файлы

### app.py
- Flask entrypoint приложения и API:
  - `/api/config`
  - `/api/database`
  - `/api/storage`
  - `/api/scales/*`
  - `/api/archive/*`, `/api/year/rotation/*` — stage-6 маршруты со structured request/result logs
  - интеграционные endpoint-ы импорта и РЭО
  - `stage6_error_response` пишет operational log через `stage6_logging` (scale logging flow не меняется)

### scale_api.py
- Runtime API весов:
  - `POST /api/scales/connect`
  - `GET /api/scales/status`
  - `POST /api/scales/read`
  - `POST /api/scales/disconnect`
  - `set_scale_transport_factory(factory)` (test helper)
  - `register_scale_api(error_response)`
  - `invalidate_for_scale_switch(site_id, from_scale_id)`
  - `invalidate_for_database_payload(changed_storage_keys)`

### scale_api_guard.py
- Backend security guard для `/api/scales/*`:
  - `ScaleApiGuard.validate_origin(request)` — allowlist origin/referer
  - `ScaleApiGuard.load_operator_context()` — persisted `app_current_user`
  - `ScaleApiGuard.require_permission(operation, operator_context)`
  - `OperatorContext` — контекст оператора

### scale_runtime.py
- Runtime-оркестрация backend session:
  - `connect()/status()/read()/disconnect()` с проверкой активного комплекта из `app_site_runtime`;
  - preflight integrity-audit перед `connect/read` для active runtime-контура;
  - `invalidate_for_runtime_change()` — закрытие старой сессии и stale-marker;
  - `invalidate_for_database_update()` — инвалидация сессий после критичных изменений `/api/database`.
  - `scale_state_lock` — process-local lock для snapshot/runtime операций.
  - redacted lifecycle logging: `open`, `read`, `disconnect`, `stale`, `error`.

### scale_integrity.py
- Integrity-audit persisted runtime-контура:
  - `run_scale_integrity_audit(connection)` — проверка `sites/scales/site_runtime/app_current_user`;
  - `AuditFinding` и `AuditReport` с разбиением findings на `fatal`/`warning`;
  - fatal findings блокируют только aut-read path.

### scale_transports/serial_backend.py
- Transport-драйвер backend serial I/O:
  - `SerialBackendTransport.open(connection)`
  - `SerialBackendTransport.read_line(timeout_ms)`
  - `SerialBackendTransport.close()`
  - `SerialBackendError` — канонические transport-ошибки.

### sqlite_store.py
- Работа с SQLite и схемой хранения:
  - `init_schema(connection)`
  - `migrate_schema_stage_5(connection)` — add-only migration (`manual_weight_reason`, `PRAGMA user_version = 5`, post-check)
  - `migrate_schema_stage_6(connection)` — add-only migration (`auto_closed`, stage-6 `ticket_audit`, обязательные индексы, `PRAGMA user_version = 6`)
  - stage-6 helpers: `read_ticket_year_range()`, `count_stage6_tables()`, `backfill_stage6_audit_columns()`, `validate_stage6_database()`
  - rotation helpers: `load_rotation_preview()`, `apply_auto_close_plan()`, `copy_whitelist_data()`, `assert_no_forbidden_runtime_keys()`, `validate_new_year_database()`
  - archive read: `map_ticket_row()`, `read_archive_tickets(db_path, filters)`, `read_archive_ticket(db_path, ticket_id)`, `read_archive_ticket_rows()` alias
  - archive edit: `read_archive_ticket_for_update(connection, ticket_id)`, `save_archive_ticket_edit(connection, ticket_id, updated_ticket)`, `insert_ticket_audit_event(connection, event)` — запись в существующую `ticket_audit`
  - legacy stub helper: `update_archive_ticket()` (ранний stub, не используется реальным edit-flow)
  - `next_ticket_number(connection)` — следующий номер талона внутри текущего year-файла
  - `read_database(db_path=None)`
  - `read_runtime_snapshot()` — атомарный runtime snapshot (`sites/scales/site_runtime/app_current_user`)
  - `write_database(data, db_path=None)`

### active_year_service.py
- Thin-слой active-year операций:
  - `read_active_storage()` — чтение только из активной годовой БД через selector
  - `write_active_storage(data, operation)` — write-gate + запись только в активную БД
  - `get_active_ticket_numbering_state()` — диагностика `active_year` и `max_ticket_number`

### year_context.py
- Selector годового контекста БД stage 6:
  - `resolve_db_context(mode, year)` — единый selector active/archive
  - `resolve_active_context()` / `resolve_archive_context(year)` — backward-compatible wrappers
  - `validate_archive_year(raw_year)` — обязательный параметр `year` в формате ГГГГ (`invalid_archive_year`)
  - `ArchiveContractError` — доменные ошибки archive API
  - `resolve_migration_year(now)` — определение года первичной миграции по датам legacy-тикетов
  - `resolve_rotation_context(...)` — канонические годы и проверка client assertions для preview/commit
  - `assert_active_db_write_allowed(...)` — единый guard write-операций active DB под lock ротации
  - `list_year_database_files()` — список годовых DB-файлов

### year_rotation.py
- Первичная миграция stage 6:
  - `ensure_stage6_storage_bootstrap(now)` — one-time bootstrap legacy->yearly + resume после publish
  - `migrate_legacy_database(now)` — copy-on-write миграция `BD/weighing.db` в `BD/weighing-YYYY.db`
  - `detect_mixed_legacy_warning(db_path, archive_year)` — warning mixed legacy
- Реальный flow ротации stage 6:
  - `build_rotation_preview(now, actor)` — dry-run авто-закрытия open-тикетов с `tara_default` fallback
  - `commit_year_rotation(...)` — commit под lock, backup, whitelist-copy в `.tmp` и publish нового года
  - `recover_rotation_if_needed(now)` — stale-lock recovery (`resume_tmp` / `rebuild_target`)
  - `preview_rotation(payload)` / `commit_rotation(payload)` — API-обёртки с server-side инвариантами годов
  - test-only hooks: `set_rotation_test_hook` / `clear_rotation_test_hooks` (`after_lock_acquired`, `after_backup`, `after_tmp_ready`, `after_whitelist_copy`) для fail/retry и parallel coverage
- Structured logs через `stage6_logging.log_stage6_event` для start/итог migration, preview/commit, lock, stale-recovery, backup, publish/config errors

### archive_service.py
- Реальный archive-read stage 6:
  - `list_archive_years(active_year)` — каталог по именам `weighing-ГГГГ.db` без открытия всех БД
  - `get_archive_tickets(year, filters)` / `list_archive_tickets(...)` — read-only журнал выбранного года
  - `get_archive_ticket(year, ticket_id)` — карточка тикета выбранного архива
  - `build_mixed_legacy_warning(year, ticket)` — warning при расхождении календарного года тикета и имени файла
- Structured logs: открытие архива, `archive_year_not_found`, `archive_open_failed`, mixed-legacy warning

### archive_edit_service.py
- Реальная admin-правка архивного тикета stage 6:
  - `validate_archive_patch(patch)` — строгий whitelist UC-05 / `archive_edit_forbidden_field`
  - `normalize_archive_patch(patch)` — нормализация строк и весов до diff
  - `recalculate_archive_ticket(ticket, patch)` — backend-пересчёт `net_weight` / `total_amount`
  - `apply_archive_edit(year, ticket_id, patch, actor, acknowledge_reo_sent_warning)` — admin-only, REO ack, одна транзакция ticket+audit
  - `patch_archive_ticket(ticket_id, payload)` — thin wrapper над `apply_archive_edit`
- Structured logs: success / forbidden / `reo_divergence_warning` / no-op (без полного old/new diff; diff только в `ticket_audit`)

### ticket_audit_stage6.py
- Формирование stage-6 audit payload:
  - `build_archive_edit_audit_event(...)` — diff `archive_edit` с `changed_fields` / old/new / `reo_divergence_warning`
  - `build_auto_close_audit_event(...)` — общий формат `auto_close` для ротации

### stage6_logging.py
- Structured operational logging для stage 6 (отдельно от `ticket_audit`):
  - `log_stage6_event(event, status, **context)` — единый JSON-лог в `logs/app.log` (`stage6 {...}`)
  - `redact_sensitive_stage6_context(context)` — маскирование `reo_access_key`, `*_db_password`, токенов и connection payload
  - обязательные поля: `event`, `status`; по применимости — `source_year`, `target_year`, `db_path`, `backup_path`, `operator_*`, `open_count`, `auto_closed_count`, `pending_reo_count`, `lock_path`, `lock_phase`, `reason`
