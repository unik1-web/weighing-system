# Каталог: server/tests/

## Назначение
Pytest-набор backend: schema, API-контракты, runtime и регрессионные проверки.

## Файлы

### test_scale_api_stub_smoke.py
- Интеграционные тесты runtime API весов:
  - `connect -> status -> read -> disconnect`
  - `inactive_scale_mismatch` на `connect`
  - `unsupported_transport` для `tcp_client`
  - проверка единого error body (`code`, `message`)

### test_scale_runtime_switch.py
- Интеграционные тесты переключения active комплекта:
  - stale-session после switch runtime;
  - `status/read/disconnect` возвращают `409 stale_session`;
  - unrelated `/api/database` update не инвалидирует session.

### conftest.py
- Общие фикстуры:
  - изоляция `config.ini` и SQLite в temp-каталоге;
  - Flask test-client;
  - reset runtime session registry перед каждым тестом API;
  - подмена transport factory для deterministic serial runtime tests;
  - `temp_stage6_root` — изолированный app root для stage 6;
  - autouse-очистка `year_rotation` test hooks между тестами;
  - реэкспорт stage-6 helpers: `build_stage6_legacy_db`, `build_stage6_active_year_db`, `build_stage6_archive_db`, `freeze_stage6_now`, `corrupt_tmp_database`, `age_stage6_lock`.

### stage6_fixtures.py
- Программные builders временных SQLite-фикстур stage 6 (через `sqlite_store.init_schema`):
  - mixed legacy / empty legacy;
  - rotation-source (open tickets, pending REO, whitelist, optional extra `app_*`);
  - archive tickets (sent REO, mixed-legacy dates);
  - freeze now / corrupt tmp / age lock helpers.

### test_scale_api_guard.py
- Security tests runtime API:
  - `origin_not_allowed` для неразрешённого origin;
  - `auth_required` без active operator-session.

### test_scale_api_contract.py
- Контрактные тесты `/api/scales/*`:
  - success flow `connect -> status -> read -> disconnect`;
  - error-контракты `inactive_scale_mismatch`, `stale_session`, `invalid_connection_config`, `unsupported_transport`, `transport_unavailable`, `read_timeout`;
  - проверка стандартного error payload (`success/code/message`).

### test_scale_api_security.py
- Security guard `/api/scales/*`:
  - отказ для неразрешённого `Origin`;
  - `auth_required` без active operator-session;
  - `insufficient_permissions` при недостаточной роли;
  - отсутствие wildcard CORS (`Access-Control-Allow-Origin: *`).

### test_scale_runtime_registry.py
- Lifecycle тесты runtime session registry:
  - идемпотентный `connect`;
  - stale после switch/config write;
  - идемпотентный `disconnect`;
  - purge истёкших stale-marker;
  - `session_registry_overloaded` при переполнении.

### test_scale_adapter_parity.py
- Backend parity tests по shared fixture-pack:
  - built-in adapters;
  - `generic-regex` runtime fixtures.

### test_scale_integrity.py
- Unit-тесты integrity-аудита и redacted logging:
  - различение `fatal` и `warning` findings;
  - скрытие приватных `COM/TTY/IP` в structured runtime logs.

### test_serial_backend_transport.py
- Unit tests `SerialBackendTransport`:
  - timeout mapping (`read_timeout`);
  - open/read transport failures (`transport_unavailable`).

### test_stage5_migration.py
- Unit/E2E tests migration runbook stage 5:
  - backup/import round-trip для `manual_weight_reason_policy`, `manual_weight_reason`, `connection_json`;
  - идемпотентный повторный запуск `migrate_legacy_storage()` с `PRAGMA user_version = 5`;
  - проверка создания backup-пары `config.ini` + `BD/weighing.db`.

### test_smoke_yearly_archive_evidence.py
- Unit-тесты evidence renderer `scripts/smoke_yearly_archive.py`:
  - markdown/json со статусами PASS/FAIL по шагам;
  - регистрация CLI scenarios `active` / `archive` / `fail-retry` / `parallel-lock`.

### test_stage6_stub_skeleton.py
- Unit/E2E tests каркаса stage 6:
  - `get_sqlite_path(year, suffix)` для legacy/year/tmp путей;
  - `read_active_year()`/`write_active_year()` через `config.ini[settings]`;
  - add-only `migrate_schema_stage_6()` (колонки, индексы, `user_version = 6`);
  - smoke-контракты новых endpoint-ов `/api/archive/*` и `/api/year/rotation/*`;
  - проверка совместимости `/api/config` и `/api/database` после подключения stage-6 каркаса.

### test_stage6_stub_contract.py
- Контрактные проверки stage-6 archive/rotation:
  - обязательные поля в ответах `/api/archive/*` и `/api/year/rotation/*`;
  - валидация кода `invalid_archive_year` при отсутствии параметра `year`;
  - no-mock запуск `scripts/smoke_yearly_archive.py` против реального HTTP entrypoint `python server/app.py`.

### test_archive_read_flow.py
- Тесты archive-read (каталог лет, журнал, карточка, reprint isolation):
  - `list_archive_years` по именам файлов (исключает active year / `.tmp` / invalid);
  - `validate_archive_year` только для ГГГГ;
  - `build_mixed_legacy_warning` при расхождении даты тикета и года файла;
  - E2E: список 20 архивов, открытие выбранного года без изменения active DB;
  - E2E: mixed legacy warning сохраняет выбранный год;
  - E2E: чтение completed ticket не копирует запись в active year;
  - E2E: повреждённый архив → `archive_open_failed`, другой год остаётся доступен.

### test_archive_edit_flow.py
- Тесты admin-правки архива и diff-аудита:
  - unit: `validate_archive_patch`, `recalculate_archive_ticket`, `build_archive_edit_audit_event`;
  - E2E: admin PATCH сохраняет allowlist-поля и пишет `ticket_audit.archive_edit`;
  - E2E: non-admin → `403 insufficient_permissions`;
  - E2E: `reo_status=sent` без ack → `409 archive_reo_ack_required`, с ack → warning и статус `sent`;
  - E2E: forbidden fields / no-op diff без записи аудита;
  - smoke: active journal не меняется после archive edit.

### test_stage6_primary_migration.py
- Тесты задачи 2.1 (первичная миграция legacy -> yearly):
  - `resolve_migration_year()` по данным тикетов и для пустой БД;
  - copy-on-write операции `create_database_backup` / `create_tmp_copy_from_legacy` / `publish_tmp_database`;
  - backfill новых stage-6 колонок `ticket_audit`;
  - E2E-сценарии mixed legacy, empty legacy, target conflict, resume после сбоя между publish и `write_active_year`.

### test_stage6_rotation_flow.py
- Тесты задачи 2.2 (preview/commit ротации):
  - preview для `open`-тикетов (dictionary tare + `tara_default`) без записи в БД;
  - guard `assert_active_db_write_allowed` для fresh/stale lock и `allow_rotation_commit=True`;
  - whitelist-copy и deny-by-default проверка runtime/session данных target DB;
  - успешный commit: backup, auto-close + `ticket_audit`, publish нового года, очистка сессии;
  - блокировка параллельного commit (`rotation_in_progress`) и stale-lock recovery (`resume_tmp`).

### test_active_year_service.py
- Тесты active-year CRUD слоя:
  - `next_ticket_number()` для пустой/заполненной годовой БД;
  - `write_active_storage()` с write-gate (`rotation_in_progress`);
  - диагностика `get_active_ticket_numbering_state()`.

### test_stage6_logging.py

  - E2E/unit: archive-edit success/forbidden/noop/warning без полного diff; diff только в `ticket_audit`.

### test_stage6_migration.py

### test_stage6_rotation.py
