# Постановка: два режима взвешивания (одиночное / двойное)

> **Статус:** реализовано (этап 1). Деплой/миграция: [docs/weighing-modes-deploy.md](../weighing-modes-deploy.md).  
> Файл сохранён как эталон постановки и вход для регрессий; новые прогоны оркестратора — с [02-weight-source.md](02-weight-source.md).

## Цель

Реализовать паритет с Vescom StaticTruckScale по режимам взвешивания: **одиночное** и **двойное**, чтобы оператор мог завершать рейс за один проход или за два (брутто → тара / тара → брутто) без обходных путей.

Источник требований: [docs/roadmap.md](../roadmap.md), этап 1.

## Контекст as-is

- Тикет: `WeighingTicket` со статусами `open` | `completed` (`src/lib/storage.ts`).
- Источник веса: только `manual` | `instrument`.
- Один активный Web Serial-терминал; подстановка по номеру — марка и стандартная тара.
- Дозавершение `open`-тикетов из формы и журнала слабое / неполное.
- Нет полей `weighing_mode`, настроек `weighing_mode_default`, `tara_threshold`, `max_time_between`, `tara_default`, `stable_mode`.
- Нет `version` и зачатка `ticket_audit`.

Стек и ограничения: [docs/project-for-agents.md](../project-for-agents.md), [docs/architecture.md](../architecture.md), [docs/api.md](../api.md).

## Что сделать

### Режимы

1. **Одиночное** — один проход:
   - фиксируется брутто (с весов или вручную);
   - тара берётся из карточки автомобиля или из `tara_default`;
   - тикет сразу `completed`.

2. **Двойное** — два прохода:
   - первый проход → тикет `open` с первым весом;
   - второй проход → выбор незавершённого тикета (форма и журнал), фиксация второго веса, расчёт нетто, статус `completed`;
   - применить `tara_threshold` (автоподсказка брутто/тара по величине веса);
   - предупреждение, если интервал между проходами > `max_time_between`.

### Настройки (`config.ini` / UI настроек)

Добавить (или расширить существующую секцию):

| Ключ | Смысл |
|------|--------|
| `weighing_mode_default` | `single` \| `dual` — режим по умолчанию на форме |
| `stable_mode` | фиксация при нестабильном весе (как в Vescom; уточнить поведение по коду весов) |
| `tara_threshold` | порог автоопределения брутто/тара |
| `max_time_between` | макс. интервал между проходами двойного взвешивания |
| `tara_default` | тара по умолчанию, если нет в справочнике авто |

### Данные

- Поле `weighing_mode` на тикете (`single` \| `dual`).
- Зачаток оптимистичной блокировки: `version` на тикете.
- Минимальный `ticket_audit` (или эквивалент): кто/когда создал и завершил; без полной правки архива (это этап 6–7 roadmap).

### UI

- Переключатель режима на форме взвешивания (с учётом default из настроек).
- Панель / список **«Незавершённые»** для двойного режима.
- Дозавершение `open` из формы и из журнала.
- Не ломать печать, РЭО, импорт Vescom/Metra/WA, существующие API-контракты без явной необходимости.

## Вне скоупа этой постановки

- Площадка primary/spare, камеры, ANPR.
- Расширение `WeightSource` до `dictionary` / `default` как отдельный этап (этап 2) — здесь достаточно корректно брать тару из справочника/`tara_default` для одиночного режима; источник веса можно оставить совместимым с as-is, если этап 2 ещё не начат (аналитик зафиксирует в ТЗ).
- Годовая ротация БД, полная автоподстановка ФИО/груза, адаптеры терминалов.

## Критерии приёмки

- [ ] Оператор выбирает одиночное или двойное; default берётся из настроек.
- [ ] Одиночное: один проход → `completed`; тара из карточки авто или `tara_default`.
- [ ] Двойное: первый проход → `open`; второй из формы и из журнала → `completed` с корректным нетто.
- [ ] Список незавершённых показывает только релевантные `open`-тикеты.
- [ ] Предупреждение при превышении `max_time_between`.
- [ ] `tara_threshold` влияет на подсказку брутто/тара (поведение описано в ТЗ и покрыто тестами).
- [ ] Настройки сохраняются в `config.ini` и поднимаются после перезапуска.
- [ ] Регрессии: журнал, печать акта/талона, РЭО, импорты — без поломок happy-path.
- [ ] Есть unit/интеграционные тесты на ключевые сценарии (фронт и/или `server/tests` по месту логики).
