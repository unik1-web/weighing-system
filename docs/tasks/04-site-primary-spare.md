# Постановка: площадка — основные и резервные весы

> **Статус:** реализовано (этап 4). Следующий оркестраторный прогон — [05-scale-adapters.md](05-scale-adapters.md) (параллельно возможен [06-yearly-db-archive.md](06-yearly-db-archive.md)).

## Цель

Ввести модель площадки с комплектами **основные / резервные** весы, runtime активного комплекта и журналируемым переключением, чтобы каждый новый талон знал `scale_id` / `scale_role`, а на spare ANPR был выключен конфигурацией (`disabled_by_configuration`) даже до внедрения ANPR.

Источник требований: [docs/roadmap.md](../roadmap.md), этап 4.  
Зависимости: этапы 1–3 желательны (форма/тикет/resolve); камеры и ANPR — заготовки режимов, без полного UI фото.

## Контекст as-is

- Один логический терминал Web Serial; нет сущностей `sites` / `scales` / `site_runtime`.
- В тикете нет `site_id`, `scale_id`, `scale_role` (или только nullable stubs этапа 3).
- Нет переключателя комплекта и wizard «на резерв».

Стек: [docs/project-for-agents.md](../project-for-agents.md), [docs/architecture.md](../architecture.md), [docs/api.md](../api.md).

## Что сделать

### Данные

- Сущности: `sites`, `scales` (`role: primary|spare`, `adapter_id`, connection JSON), `site_runtime` (`active_scale_set`, switch reason/by/at, `camera_mode`, `anpr_mode`).
- Миграция: текущее подключение весов → primary на площадке по умолчанию.
- Новые талоны пишут `scale_id` / `scale_role` (и `site_id` при наличии) активного комплекта.

### Переключение комплекта

- UI: «Основные / Резервные».
- Обязательные атрибуты переключения: причина (`ремонт` | `очистка` | `поверка` | `другое`), оператор, время.
- При смене меняются: активный терминал/адаптер, поля талона для новых записей, `camera_mode`, `anpr_mode`.
- На spare: `anpr_mode = disabled_by_configuration` (даже до этапа 8).

### Wizard на резерв

- Поток: повернуть камеры → сверить с эталоном **или** чеклист до появления камер (этап 7) → подтвердить → ввод номера вручную.
- До камер допустим упрощённый чеклист (аналитик зафиксирует минимальный набор шагов).

### UI

- Настройки площадки/весов.
- Индикация активного комплекта (минимум в настройках; шапка формы может быть тонкой заготовкой под этап 9).

## Вне скоупа

- Полные адаптеры протоколов (этап 5) — достаточно привязки текущего Web Serial-профиля как primary.
- Захват фото и ANPR-инференс (этапы 7–8).
- Годовая ротация (этап 6).

## Критерии приёмки

- [ ] Есть площадка по умолчанию и primary-scale из текущего подключения.
- [ ] Переключение primary ↔ spare журналируется (причина, кто, когда).
- [ ] Новый талон всегда содержит комплект весов (`scale_id` / `scale_role`).
- [ ] На spare `anpr_mode = disabled_by_configuration`.
- [ ] Wizard/чеклист на резерв проходит без блокировки взвешивания при отсутствии камер.
- [ ] Регрессии: single/dual, resolve, журнал, печать, РЭО, импорты.
- [ ] Тесты миграции и переключения runtime.

## Ограничения

- Не менять стек; артефакты в `docs/implementation/`.
- Совместимость старых тикетов: nullable поля + default site/primary.
