# Постановка: ANPR

## Цель

Локальное распознавание номера с кадра общего ракурса: предложение номера + confidence → подтверждение/правка оператором → `resolveVehicle` → подстановка справочников; на spare движок не вызывается (`disabled_by_configuration`); релиз функции при ≥ 50% на спайке объекта.

Источник требований: [docs/roadmap.md](../roadmap.md), этап 8.  
Зависимости: этап 7 (кадр/ROI), этап 4 (`anpr_mode`), этап 3 (`resolveVehicle` / автоподстановка).

## Контекст as-is

- После этапов 4 и 7: камеры, ROI, `anpr_mode`, фотопривязка.
- Нет `server/anpr.py` / локальной модели, нет потока подтверждения номера.
- Принцип roadmap: оператор в контуре — номер только после подтверждения/правки.

Стек: [docs/project-for-agents.md](../project-for-agents.md), [docs/architecture.md](../architecture.md), [docs/api.md](../api.md).

## Что сделать

### Поток

```text
кадр → локальная модель → номер + confidence
     → UI подтверждения оператором
     → plate_source / anpr_* в тикете
     → resolveVehicle → подстановка справочников
```

### Данные в тикете

- `anpr_plate_raw`, `plate_confidence`, `anpr_accepted`, `plate_source` (`anpr` | `operator` | `directory`), `anpr_status` (`enabled` | `disabled_by_configuration` | `failed`).

### Режимы

- Primary: ANPR доступен при `anpr_mode`/`video_enabled` согласно настройкам.
- Spare / `disabled_by_configuration`: движок **не** вызывается; в отчётах это не сбой.
- Ошибка модели/кадра → `failed` (отличимо от «выкл. конфигом»).

### Спайк и релиз

- Спайк на объекте (день/ночь/дождь/грязные номера) — процедура/чеклист в ТЗ или deploy-доке.
- Порог релиза: ≥ 50% точности; иначе ANPR выкл. по умолчанию, ручной ввод без изменений.

### UI

- Подсказка номера с confidence; принять / править / ввести вручную.
- После принятия — та же автоподстановка, что на этапе 3.

## Вне скоупа

- Внешняя СКУД / облачное распознавание.
- Отдельная длиннофокусная камера на резерве (опционально позже).
- Полный редизайн отчётов (часть — этап 9).

## Критерии приёмки

- [ ] На primary — подсказка номера с подтверждением оператором.
- [ ] На spare — только ручной/справочник; движок не вызывается.
- [ ] Отчёты/поля различают `disabled_by_configuration` и `failed`.
- [ ] После подтверждения номера срабатывает resolve/подстановка.
- [ ] При выкл. ANPR или точности ниже порога ручной сценарий не деградирует.
- [ ] Регрессии: фото, primary/spare, single/dual.
- [ ] Тесты статусов ANPR и ветки «движок не вызван на spare».

## Ограничения

- Локальная модель; веса/модели — вне git или документированный способ поставки в полной сборке.
- Артефакты пайплайна в `docs/implementation/`.
- Не коммитить персональные кадры с объекта без необходимости.
