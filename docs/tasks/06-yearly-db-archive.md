> **Статус:** реализовано (этап 6). Деплой/миграция: [docs/yearly-db-archive-deploy.md](../yearly-db-archive-deploy.md). Acceptance: [docs/reports/yearly-db-archive/yearly-archive-acceptance.md](../reports/yearly-db-archive/yearly-archive-acceptance.md). Следующий оркестраторный прогон — [07-photo-capture.md](07-photo-capture.md).

## Цель

Ввести годовые файлы SQLite (`BD/weighing-ГГГГ.db`), ротацию года с закрытием забытых `open`, переносом справочников/пользователей/`vehicle_drivers` и архивным просмотром; дать `admin` правку архива с аудитом и предупреждением при уже отправленных в РЭО.

Источник требований: [docs/roadmap.md](../roadmap.md), этап 6.  
Зависимости: этапы 1–3 (режимы, источники, `vehicle_drivers`); может идти параллельно с 4–5 по roadmap.

## Контекст as-is

- Один файл `BD/weighing.db`.
- Нумерация талонов сквозная в рамках файла.
- Зачаток `ticket_audit` (create/complete); нет полной правки архива admin.
- Полигон без выходных: ротация закрывает **редкие** забытые `open`, не массовый переходящий поток.

Стек: [docs/project-for-agents.md](../project-for-agents.md), [docs/architecture.md](../architecture.md), [docs/api.md](../api.md).

## Что сделать

### Файлы и конфиг

- Файлы `BD/weighing-ГГГГ.db`; активный год в `config.ini`.
- Миграция с текущего `weighing.db` → схема года (правило имени/года — в ТЗ).

### Ротация года

- Закрыть забытые `open`: тара из справочника / `tara_default`, флаг `auto_closed`; показать список оператору.
- Предупредить о pending РЭО.
- Перенести: справочники, пользователей, настройки, `vehicle_drivers`.
- **Не** переносить журнал взвешиваний в новый файл.
- Бэкап архивной `.db`.
- Нумерация талонов с 1 в новом году; на печати «№ N от ДД.ММ.ГГГГ».

### Архив

- Просмотр и перепечатка архивных тикетов.
- Роль `admin`: правка с записью в `ticket_audit` / `ticket_revisions` (кто, когда, старое/новое).
- Предупреждение при `reo_status = sent`.

## Вне скоупа

- Камеры/ANPR (пути фото nullable — не удалять).
- Смена стека хранения.

## Критерии приёмки

- [x] Смена года сохраняет справочники, пользователей и `vehicle_drivers`.
- [x] Журнал прошлого года остаётся в архивном файле и читается.
- [x] Нумерация в новом году с 1; печать с датой.
- [x] Забытые `open` закрываются с `auto_closed` и показываются оператору.
- [x] Admin-правка архива пишется в audit; предупреждение при sent в РЭО.
- [x] Бэкап архивной БД создаётся при ротации.
- [x] Регрессии: текущий год single/dual, РЭО, импорты.
- [x] Тесты ротации (на временных файлах БД) и правки архива.

## Ограничения

- Не менять стек; данные рядом с программой (не в `_MEIPASS`).
- Артефакты пайплайна в `docs/implementation/`.
- Не коммитить `BD/`, бэкапы, секреты.
