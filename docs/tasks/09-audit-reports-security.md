# Постановка: аудит, отчёты, документация, безопасность

## Цель

Закрыть операционный и документальный контур roadmap: режим площадки в шапке формы, журнал переключений комплекта, полный `ticket_audit`, расширенные фильтры/CSV/карточка, актуальные `docs/*` и README, серверный hash паролей и смена дефолтного `admin` при первом входе.

Источник требований: [docs/roadmap.md](../roadmap.md), этап 9.  
Зависимости: этапы 1–8 по факту внедрения (минимум 1–4 и 6 для аудита/архива; фото/ANPR-поля — если уже есть).

## Контекст as-is

- Зачаток audit (create/complete); нет полного журнала изменений полей.
- Нет единого индикатора primary/spare/ANPR/камер в шапке формы.
- Фильтры/CSV не покрывают площадку, весы, фото, ANPR-статус.
- Пароли: `btoa` на клиенте (небезопасно); дефолт `admin` / `admin123`.

Стек: [docs/project-for-agents.md](../project-for-agents.md), [docs/architecture.md](../architecture.md), [docs/api.md](../api.md).

## Что сделать

### Операционный UI

- Режим площадки в шапке формы: primary/spare, статус ANPR, камеры (если функции собраны).
- Журнал переключений комплекта весов (из этапа 4) — доступный просмотр.

### Аудит

- Полный `ticket_audit` (и/или `ticket_revisions`): кто, когда, старое/новое по значимым полям.
- Согласовать с правкой архива этапа 6; не дублировать противоречащие модели.

### Отчёты и журнал

- Фильтры / CSV / карточка: площадка, весы, источники веса, наличие фото, ANPR-статус, режим взвешивания, оператор.
- Не выводить источник веса на печатной форме (если не изменится требование).

### Документация

- Обновить `docs/architecture.md`, `docs/api.md`, README под фактическое состояние после этапов.
- Кратко отразить базовую vs полную сборку установщика.

### Безопасность

- Серверный hash паролей вместо `btoa`.
- Принудительная смена дефолтного `admin` при первом входе (или эквивалентный безопасный onboarding).

## Вне скоупа

- Новая длиннофокусная камера на spare (опционально позже в roadmap).
- Смена стека auth (OAuth и т.п.).

## Критерии приёмки

- [ ] Шапка формы отражает активный режим площадки и статусы камер/ANPR (если включены).
- [ ] Журнал переключений комплекта доступен.
- [ ] Полный audit правок тикета; история видна в карточке (роль/права — в ТЗ).
- [ ] Фильтры и CSV содержат площадку, весы, источники, фото, ANPR.
- [ ] Документация и README соответствуют коду.
- [ ] Пароли хранятся как серверный hash; дефолтный admin принуждён к смене.
- [ ] Регрессии: вход, журнал, РЭО, печать, импорты.
- [ ] Тесты hash/login и ключевых фильтров отчётов.

## Ограничения

- Не менять стек; артефакты в `docs/implementation/`.
- Не коммитить секреты, `.env`, боевые пароли.
- Обратная совместимость сессий/пользователей при миграции hash — описать в ТЗ.
