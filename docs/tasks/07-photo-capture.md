# Постановка: фотофиксация

## Цель

Подключить IP-камеры / RTSP (полная сборка): снимок при фиксации брутто/тары, хранение файлов на диске и метаданных в `ticket_photos`, превью в форме и журнале; graceful degrade без блокировки взвешивания при недоступности камер.

Источник требований: [docs/roadmap.md](../roadmap.md), этап 7.  
Зависимости: этап 4 (реестр камер площадки, эталоны primary/spare, `camera_mode`); желательно этап 5 для стабильного комплекта весов.

## Контекст as-is

- Нет модуля камер, каталога `Photo/`, таблицы `ticket_photos`.
- Есть (после этапа 4) заготовки `camera_mode` и сущности камер — либо создать их здесь, если этап 4 сделал минимальный чеклист без реестра.
- Две поставки `.exe`: базовая (без камер) и полная (фото + позже ANPR).

Стек: [docs/project-for-agents.md](../project-for-agents.md), [docs/architecture.md](../architecture.md), [docs/api.md](../api.md).

## Что сделать

### Настройки и реестр

- `video_enabled`; 1–4 камеры; RTSP/HTTP snapshot; каталог `Photo/` (или `BD/photos/{ticket_id}/…` рядом с exe, не в `_MEIPASS`).
- Реестр камер площадки (`role: entry|exit|overview`, capture URL).
- Эталонные снимки ракурса primary/spare (для wizard этапа 4).
- В полной сборке — переключатель без переустановки; базовая сборка без OpenCV/моделей.

### Захват

- Снимок при фиксации брутто/тары со включённых камер.
- Для будущего ANPR — кадр выбранной камеры общего ракурса (+ ROI в настройках).
- JPEG умеренного качества; при недоступности камеры — не блокировать взвешивание (graceful degrade, лог).

### Данные и UI

- Таблица `ticket_photos` (пути/метаданные; бинарники не в SQLite).
- Превью в форме и карточке журнала.
- Поля тикета со ссылками на фото (если заложены в этапе 3) заполняются.

## Вне скоупа

- ANPR-инференс и порог точности (этап 8).
- Отдельная длиннофокусная камера как продукт — опционально позже (roadmap §9).

## Критерии приёмки

- [ ] При доступных камерах у сохранённого тикета есть снимки брутто/тары (по включённым камерам).
- [ ] Недоступность камеры не блокирует завершение взвешивания.
- [ ] Файлы на диске рядом с программой; в БД — пути/метаданные.
- [ ] Превью в форме и журнале.
- [ ] `video_enabled` управляет функцией в полной сборке; базовая сборка собирается без тяжёлых зависимостей камер (или явно документированный exclude).
- [ ] Эталоны primary/spare сохраняются и доступны wizard’у.
- [ ] Регрессии: primary/spare, single/dual, печать без обязательных фото.
- [ ] Тесты сохранения метаданных и degrade-пути (моки камеры).

## Ограничения

- Не менять стек; артефакты в `docs/implementation/`.
- Не коммитить образцы RTSP URL с секретами, бинарники фото.
- Печатные формы не обязаны включать фото на этом этапе (если не потребует ТЗ явно).
