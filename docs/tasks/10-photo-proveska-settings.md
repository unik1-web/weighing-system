# Постановка: фото провески, терминология, README и вкладки настроек

## Цель

Исправить недоступность фото после взвешивания («Фото недоступно»), обеспечить показ снимков по числу камер при просмотре провески, заменить в UI термин «тикет» на «провеска», дополнить README по настройке камер и кнопкам, разнести настройки по вкладкам, открываемым по выбору.

Источник: запрос заказчика после этапов 07–09 (фото, ANPR, UX).  
Зависимости: этап 7 (камеры / `ticket_photos`), желательно монитор камер на форме взвешивания и preview в настройках (если уже влиты).

## Контекст as-is

- После сохранения взвешивания часто сообщение: «Взвешивание завершено и сохранено. Фото недоступно» (`triggerCaptureAfterSave` / degrade-путь), хотя камеры настроены.
- В карточке/просмотре не всегда видны фото по количеству включённых камер площадки.
- В интерфейсе и части текстов пользователю показывается «тикет»; ожидаемый термин — **«провеска»**.
- README слабо описывает настройку камер и назначение кнопок (проверка снимка, эталоны, монитор на весах и т.п.).
- Экран настроек — длинная простыня секций; нужна навигация вкладками по группам параметров.

Стек: [docs/project-for-agents.md](../project-for-agents.md), [docs/architecture.md](../architecture.md), [docs/api.md](../api.md).

## Что сделать

### 1. Фото после взвешивания

- Выяснить и устранить причину «Фото недоступно» при включённом `video_enabled` и валидных камерах (sync/FK, захват до/после POST database, пути `Photo/`, HTTP vs RTSP/OpenCV, гонка сохранения).
- При успешном захвате сообщение об успехе **не** должно утверждать, что фото недоступно; при частичном fail — честная формулировка («часть фото недоступна»).
- Регрессии: single/dual, primary/spare, `video_enabled=false` (без фото — без ложной паники).

### 2. Просмотр провески: фото по камерам

- В карточке/просмотре (журнал, форма после сохранения) показывать превью **по числу включённых камер** (или по фактически сохранённым `ticket_photos` с понятным статусом ok/failed/skipped на слот).
- Не оставлять пустой блок, если съёмка ожидалась; failed — явная пометка, не «тишина».

### 3. Терминология: «провеска»

- В пользовательском UI (русский) заменить «тикет» / «талон» где это обращено к оператору на **«провеска»** (кнопки, заголовки, тосты, журнал, пустые состояния).
- Технические идентификаторы кода/API (`ticket_id`, `weighing_tickets`, пути) можно не переименовывать; важно единообразие **видимого** текста.
- Пройти основные экраны: взвешивание, журнал, архив, настройки (если есть), печать — без смеси терминов в одном экране.

### 4. README

- Раздел по **настройке камер**: `video_enabled`, реестр 1–4 камер, URL HTTP/RTSP, роли, ROI overview, эталоны primary/spare, OpenCV для RTSP (`requirements` / полная сборка).
- Описание **кнопок**: «Показать снимок» / эталоны в настройках; монитор «Камеры на весах» на форме; действия при сохранении веса.
- Кратко: где смотреть фото провески после сохранения.

### 5. Настройки: вкладки по группам

- Экран настроек разбить на **вкладки** (или эквивалентный выбор раздела), например: организация / весы и площадка / камеры и фото / режимы взвешивания / интеграции (РЭО, Vescom, …) / безопасность / прочее — по фактическим блокам.
- Одновременно открыт один раздел (контент по выбору вкладки); не одна бесконечная простыня.
- Сохранение настроек не ломать; активная вкладка может запоминаться в session (опционально).

## Вне скоупа

- Новый движок ANPR / смена модели.
- Облачное хранение фото.
- Полный i18n-фреймворк (только замена видимых русских строк «тикет»→«провеска»).

## Критерии приёмки

- [ ] При рабочих камерах и `video_enabled=true` после сохранения нет ложного «Фото недоступно»; фото пишутся на диск и в метаданные.
- [ ] В просмотре провески видны слоты/превью согласованно с камерами (или явный статус по каждой).
- [ ] В UI для оператора используется «провеска», без доминирующего «тикет» на основных экранах.
- [ ] README содержит инструкцию по камерам и кнопкам.
- [ ] Настройки открываются по вкладкам/разделам по выбору.
- [ ] Регрессии: взвешивание без видео, журнал, печать, primary/spare.
- [ ] Тесты или ручной чеклист на capture success path и отображение превью.

## Ограничения

- Не коммитить боевые RTSP URL с паролями, бинарники Photo/, секреты.
- Не менять стек; артефакты пайплайна в `docs/implementation/` или `docs/{task_id}/`.
