# Постановка: источник веса и ручной ввод

> **Статус:** реализовано на ветке оркестратора (задача `7b2254-weight-source`).  
> Артефакты: [docs/7b2254-weight-source/](../7b2254-weight-source/). Следующий прогон — [03-vehicle-resolve.md](03-vehicle-resolve.md).

## Цель

Расширить модель источника веса до паритета с целевой схемой roadmap (`instrument` / `manual` / `dictionary` / `default`), исправить неверную запись автотары как `manual` и дать оператору/отчётам видимость источника без изменения печатных форм.

Источник требований: [docs/roadmap.md](../roadmap.md), этап 2.  
Зависимости: этап 1 (режимы single/dual) — [01-weighing-modes.md](01-weighing-modes.md).

## Контекст as-is (после этапа 1)

- `WeightSource = 'manual' | 'instrument'` (`src/lib/storage.ts`).
- Автотара из карточки авто / `tara_default` в одиночном режиме пишется как `manual`.
- Бейджи источника на форме / фильтр в журнале / сводка в отчётах — отсутствуют или неполные.
- Печать акта/талона не должна показывать источник веса (ограничение roadmap).
- Есть `weighing_mode`, `version`, зачаток `ticket_audit`.

Стек и ограничения: [docs/project-for-agents.md](../project-for-agents.md), [docs/architecture.md](../architecture.md), [docs/api.md](../api.md).

## Что сделать

### Модель данных

Расширить `WeightSource`:

| Значение | Смысл |
|----------|--------|
| `instrument` | С терминала |
| `manual` | Ввод с клавиатуры |
| `dictionary` | Тара из карточки автомобиля |
| `default` | Тара из `tara_default` |

- Миграция/нормализация существующих тикетов: прежние `manual`/`instrument` сохранить; автотара, если её можно отличить по правилам этапа 1 — по возможности переклассифицировать (аналитик зафиксирует безопасное правило; иначе только новые записи).
- Поля `gross_source` / `tare_source` используют расширенный тип.

### Поведение формы

- Автоподстановка тары из справочника → `tare_source = dictionary`.
- Автоподстановка из `tara_default` → `tare_source = default`.
- Ручной ввод / правка оператором → `manual`; сброс оператором не должен «возвращаться» эффектом автоподстановки без явного действия.
- Фиксация с прибора → `instrument`.
- Бейджи у полей брутто/тара с понятными подписями на русском.

### Журнал и отчёты

- Фильтр журнала по источнику веса (брутто и/или тара — зафиксировать в ТЗ).
- Сводка в отчётах: распределение / счётчики по источникам (без ломки существующих отчётов).
- Печатные формы **не менять** (источник на печати не выводить).

## Вне скоупа этой постановки

- Площадка primary/spare, камеры, ANPR.
- Полная автоподстановка ФИО/груза/водителей (этап 3).
- Адаптеры терминалов, годовая ротация, полная правка архива.

## Критерии приёмки

- [ ] У каждого **нового** сохранённого тикета корректный `gross_source` / `tare_source` из расширенного набора.
- [ ] Автотара из справочника не пишется как `manual`; из `tara_default` — как `default`.
- [ ] Сброс/правка оператором не восстанавливает автотару «эффектом» без явного действия.
- [ ] Бейджи на форме отображают источник.
- [ ] Фильтр журнала по источнику работает.
- [ ] Отчёты показывают сводку по источникам (или явно согласованный минимум в ТЗ).
- [ ] Печать акта/талона без источника веса; РЭО и импорты без регрессий happy-path.
- [ ] Unit/интеграционные тесты на классификацию источника и фильтр.
