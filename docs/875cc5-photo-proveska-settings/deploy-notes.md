# Заметки по развёртыванию: 875cc5-photo-proveska-settings (этап 10)

Кратко для поставки после этапа 10 (надёжность фото / термин «провеска» / вкладки настроек). Секреты, `config.ini`, `BD/`, бинарники `Photo/`, `.env*` и RTSP URL с паролями в git не коммитить.

## Что меняется для оператора

| Область | Поведение |
|---------|-----------|
| Автозахват фото | После сохранения веса тикет сначала синхронизируется в SQLite, затем `POST /api/cameras/capture`. При рабочих камерах и `video_enabled` не должно быть ложного «Фото недоступно». |
| Частичный fail камер | Тост: «Часть фото недоступна»; полный fail — «Фото недоступно»; video off / нет камер — без паники. |
| Превью | В карточке после сохранения и в журнале — слот на каждую включённую камеру площадки; failed/missing видны явно. |
| Терминология | Экранный UI: «провеска» вместо «тикет»/«талон» как сущности взвешивания. Печатный документ «Талон (квитанция)» без изменений. |
| Настройки | Шесть вкладок: организация и печать; площадка и весы; камеры и фото; режимы; интеграции; год и данные. Активная вкладка в `sessionStorage` (`app_settings_tab`). Кнопка «Сохранить» общая. |

## Dual-build

| Сборка | Поведение этапа 10 |
|--------|-------------------|
| Базовая (без камер / OpenCV) | Early gate: нет enabled-камер → capture no-op без тоста; превью нейтральное / «Фотофиксация отсутствует». |
| Полная (`video_enabled` + HTTP/RTSP камеры) | Flush-before-capture; файлы в `Photo/`; rows `ticket_photos`; превью со статусами. |

OpenCV нужен для RTSP (`capture_kind` / requirements полной сборки). Подробности: корневой `README.md` (раздел камер).

## БД / sync

Новых таблиц и DDL-миграций нет.

Семантика `POST /api/database` уточнена в `docs/api.md`:

- Если в POST есть `app_weighing_tickets`, но **нет** `app_ticket_photos` — сервер **не** стирает все `ticket_photos` (preserve + orphan cleanup для удалённых тикетов).
- Полный wipe photos — только когда ключ `app_ticket_photos` присутствует в теле (как и раньше для полного replace).

Клиент на время capture вызывает `pauseDatabaseSync` → `flushDatabaseSync` → capture → `resumeDatabaseSync` → flush.

## Операционный чеклист после деплоя

1. Settings → вкладка «Камеры и фото»: `video_enabled`, 1–4 камеры, URL, роли, эталоны primary/spare.
2. «Показать снимок» / «Обновить снимок» в настройках камеры.
3. Single gross+tare (или dual first/complete) при включённом видео: нет ложного «Фото недоступно»; файлы в `Photo/`.
4. Журнал / карточка: слоты failed видны; при video off — без паники.
5. Печать «Талон (квитанция)» — заголовок без изменений.
6. Settings: переключение 6 вкладок, «Сохранить» работает.
