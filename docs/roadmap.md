# Roadmap: универсальная весовая программа

Единый план развития: эволюция текущего приложения (React + Flask + SQLite + config.ini, Windows `.exe`), без смены стека. Объединяет операционный паритет с Vescom и архитектурную модель площадки (основные / резервные весы, независимые камеры и ANPR).

РЭО и импорт Vescom / Metra / WA сохраняются. Новые подсистемы наращиваются поверх учёта взвешиваний.

---

## 1. Принципы

| Принцип | Решение |
|---------|---------|
| Стек | React + TypeScript, Flask, SQLite; данные рядом с программой |
| Поставка | Две сборки `.exe`: **базовая** (без камер) и **полная** (фото + ANPR) |
| Оператор в контуре | Распознанный номер и автоподстановки — только после подтверждения / правки оператором |
| Весы / камеры / ANPR | Моделируются **независимо**; связь — через конфигурацию площадки и активный режим |
| Резервные весы | Полноценное оборудование; на них фото доступны, ANPR выключен конфигом |
| Ручной ввод веса | Всегда возможен; источник фиксируется в БД и журнале, не на печатной форме |
| Фото | Хранение и просмотр на экране |
| Правка архива | Да, роль `admin`, с аудитом |
| Камера для номера | Общий ракурс (отдельной камеры крупным планом нет); ROI в настройках |
| Порог ANPR для релиза | ≥ 50% точности на спайке по кадрам объекта |

## 2. Текущее состояние (as-is)

| Область | Есть | Где |
|--------|------|-----|
| Журнал / талон | `WeighingTicket`, SQLite | `storage.ts`, `sqlite_store.py` |
| Источник веса | `manual` \| `instrument` | талон, форма |
| Терминалы | 4 Web Serial-профиля, один `ScaleConnection` | `scales.ts`, `ScalePanel` |
| Справочники | авто, водители, грузы, контрагенты | импорт Vescom/Metra/WA |
| Подстановка по номеру | только марка и стандартная тара | `WeighingForm.tsx` |
| Статус тикета | `open` \| `completed`; single/dual, дозавершение из формы и журнала | форма / журнал |
| Печать, РЭО, отчёты | акт, талон, CSV | `PrintAct`, `reo.ts` |
| Режимы Vescom (этап 1) | `weighing_mode`, настройки порога/интервала/тары, `version`, зачаток audit | `weighing-mode.ts`, `storage.ts` |

**Нет:** площадка primary/spare; pluggable-адаптеры; камеры и фото; ANPR; полная автоподстановка; годовая ротация БД; расширенный `WeightSource` (`dictionary`/`default`); полный аудит.

## 3. Целевая модель площадки

```text
Весовая площадка
├── Основные весы  (терминал + адаптер протокола)
├── Резервные весы (опционально)
├── Камера 1 — въезд / общий план
├── Камера 2 — выезд / общий план
└── Режим (active_scale_set):
    ├── primary  → фото + ANPR
    └── spare    → только фото, номер вручную
                   (камеры повёрнуты оператором)
```

**ANPR-статусы:** `enabled` | `disabled_by_configuration` | `failed`.

На резерве распознавание не запускается: ложный номер опаснее его отсутствия. После ввода или подтверждения номера подставляются ФИО, марка, груз, грузоотправитель, тара (из справочника / последнего рейса / истории водителей).

### Референс Vescom StaticTruckScale

Параметры, которые повторяем в настройках:

| Параметр | Смысл |
|----------|-------|
| `DefaultFirstWeightType` / `weighing_mode_default` | Одиночное или двойное по умолчанию |
| `StableMode` | Фиксация при нестабильном весе |
| `TaraThreshold` | Порог автоопределения брутто/тара |
| `MaxTimeBetween` | Макс. интервал между проходами |
| `TaraDefault` | Тара по умолчанию, если нет в справочнике |
| `[Video] CameraCount` + RTSP | Число камер |
| Recognize | Своя локальная модель, не внешняя СКУД |

Два режима оператора:

1. **Одиночное** — один проход, тара из карточки авто или `TaraDefault`.
2. **Двойное** — первый проход → `open`; второй — выбор из незавершённых и фиксация второго веса.

## 4. Схема данных (эскиз)

### Площадка и оборудование

```text
sites / scales (role: primary|spare, adapter_id, connection JSON)
cameras (role: entry|exit|overview, capture URL, эталоны primary/spare)
site_runtime (active_scale_set, switch reason/by/at, camera_mode, anpr_mode)
```

### Справочники и связи

- Предпочтения ТС: водитель, груз, грузоотправитель, марка, тара.
- `vehicle_drivers`: история водителей по машине (`last_used_at`, `use_count`) — переносится при годовой ротации.

### Источник веса (`WeightSource`)

| Значение | Смысл |
|----------|-------|
| `instrument` | С терминала |
| `manual` | Ввод с клавиатуры |
| `dictionary` | Тара из карточки автомобиля |
| `default` | Тара из `TaraDefault` |

### Талон (расширение)

Помимо текущих полей: `weighing_mode`, `site_id`, `scale_id`, `scale_role`, `scale_terminal_id`, `manual_weight_reason`, `plate_source` (`anpr` \| `operator` \| `directory`), `plate_confidence`, `anpr_status`, `anpr_accepted`, `camera_mode`, пути/ссылки на фото, `version` (оптимистичная блокировка), `auto_closed` (ротация года).

Фото на диске: `Photo/ГГГГ/ММ/ДД/…` или `BD/photos/{ticket_id}/…` (рядом с exe, не в `_MEIPASS`). Метаданные — таблица `ticket_photos`.

Исправления — `ticket_audit` / `ticket_revisions` (кто, когда, старое/новое).

## 5. Этапы

### Этап 1. Два режима взвешивания

Паритет с Vescom: одиночное и двойное.

- `weighing_mode` в тикете и настройках по умолчанию.
- Одиночное: один проход → `completed`; тара из справочника или `TaraDefault`.
- Двойное: первый проход → `open`; панель «Незавершённые», дозавершение из формы и журнала; `TaraThreshold`, предупреждение по `MaxTimeBetween`.
- Настройки: `weighing_mode_default`, `stable_mode`, `tara_threshold`, `max_time_between`, `tara_default`.
- `version` + зачаток `ticket_audit`.

**Готово, когда:** оба сценария без обходных путей; open-тикет находится и закрывается из формы и журнала.

Развёртывание/миграция: `docs/weighing-modes-deploy.md`.

---

### Этап 2. Источник веса и ручной ввод

- Расширить `WeightSource` (`instrument` / `manual` / `dictionary` / `default`).
- Исправить баг: автотара из справочника не должна писаться как `manual`; сброс оператором не должен «возвращаться» эффектом.
- UI: бейджи у брутто/тары; фильтр в журнале; сводка в отчётах.
- Печатные формы не меняем.

**Готово, когда:** у каждого сохранённого тикета корректный источник; фильтр журнала работает.

---

### Этап 3. Автоподстановка по номеру и водители

- При выборе/вводе номера: марка, тара, ФИО, груз, грузоотправитель (предпочтения ТС + последний рейс).
- Таблица `vehicle_drivers` + режим `driver_input_mode`: `vehicle` | `all` | `free`.
- Один водитель в истории → автоподстановка; иначе список с приоритетом по машине.
- Опционально: первичное заполнение при импорте Vescom/Metra/WA.
- Заготовки audit-полей в талоне (`plate_source`, `scale_role`, пути фото — nullable).
- Показ источника веса / устройства / оператора в карточке и CSV.
- Сохранение выбранной модели весов в настройках.

**Готово, когда:** частая машина заполняется за 1–2 действия; режим водителя настраивается.

---

### Этап 4. Площадка: основные и резервные весы

- Сущности `sites`, `scales`, `site_runtime` + UI в настройках.
- Миграция: текущее подключение → primary на площадке по умолчанию.
- Переключатель «Основные / Резервные»: причина (ремонт, очистка, поверка, другое), оператор, время.
- Меняются: активный терминал, адаптер, `scale_id`/`scale_role` в новых талонах, `camera_mode`, `anpr_mode`.
- Wizard на резерв: повернуть камеры → сверить с эталоном (или чеклист до появления камер) → подтвердить → ввод номера вручную.
- На spare: `anpr_mode = disabled_by_configuration` (даже до внедрения ANPR).

**Готово, когда:** талон всегда знает комплект весов; переключения журналируются.

---

### Этап 5. Адаптеры весовых терминалов

- Интерфейс `ScaleAdapter` (`connect` / `read` / subscribe); профили Микросим, Ньютон, CAS, Мидл как адаптеры.
- Адаптер «произвольный разбор» (regex / маска) без нового кода.
- Параметры в `scales.connection`.
- Web Serial сохранить; заложить backend I/O (`pyserial` / TCP, `/api/scales/*`) для primary+spare и exe без зависимости только от браузера.
- Ручной ввод с опциональной/обязательной причиной.

**Готово, когда:** новый терминал подключается конфигом или тонким адаптером; активный комплект выбирает нужный.

---

### Этап 6. Годовая база и архив

- Файлы `BD/weighing-ГГГГ.db`; активный год в `config.ini`.
- Ротация: закрыть забытые `open` (тара из справочника/`TaraDefault`, `auto_closed`), показать список оператору, предупредить о pending РЭО; перенести справочники, пользователей, настройки, `vehicle_drivers`; журнал не переносить; бэкап архивной `.db`.
- Нумерация талонов с 1 в новом году; на печати «№ N от ДД.ММ.ГГГГ».
- Архив: просмотр и перепечатка; `admin` правит с записью в `ticket_audit` и предупреждением при `reo_status = sent`.

Контекст: полигон без выходных, машины уезжают к концу дня — ротация закрывает редкие забытые `open`, не массовый «переходящий» поток.

**Готово, когда:** смена года сохраняет справочники и связи водителей; архив читается; нумерация с 1.

---

### Этап 7. Фотофиксация

Зависимость: IP-камеры / RTSP (полная сборка).

- Настройки: `video_enabled`, 1–4 камеры, RTSP/HTTP snapshot, каталог `Photo/`.
- Реестр камер площадки; эталонные снимки ракурса primary/spare.
- Снимок при фиксации брутто/тары со включённых камер; для ANPR — кадр выбранной камеры общего ракурса (+ ROI).
- `ticket_photos`; JPEG с умеренным качеством; graceful degrade при недоступности камеры.
- Превью в форме и карточке журнала.
- В полной сборке — переключатель без переустановки; базовая сборка без OpenCV/моделей.

**Готово, когда:** у сохранённого тикета есть снимки (если камеры доступны); взвешивание не блокируется без камер.

---

### Этап 8. ANPR

Зависимость: этап 7 + `anpr_mode` с этапа 4.

Поток: кадр → локальная модель → предложение номера + confidence → подтверждение оператором → `resolveVehicle` → подстановка справочников.

- В тикете: `anpr_plate_raw`, `plate_confidence`, `anpr_accepted`, `plate_source`, `anpr_status`.
- На `disabled_by_configuration` движок не вызывается; в отчётах это не сбой.
- Спайк на объекте (день/ночь/дождь/грязные номера); релиз ANPR при ≥ 50%, иначе выкл. по умолчанию.

**Готово, когда:** на primary — подсказка с подтверждением; на spare — только ручной/справочник; отчёты различают «выкл. конфигом» и `failed`.

---

### Этап 9. Аудит, отчёты, документация, безопасность

- Режим площадки в шапке формы (primary/spare, ANPR, камеры).
- Журнал переключений комплекта; полный `ticket_audit`.
- Фильтры/CSV/карточка: площадка, весы, источники, наличие фото, ANPR-статус.
- Обновить `docs/architecture.md`, `docs/api.md`, README.
- Пароли: серверный hash вместо `btoa`; смена дефолтного `admin` при первом входе.

**Опционально позже:** отдельная длиннофокусная камера для ANPR на резервных весах — как ещё одна камера с `anpr_enabled` в режиме spare.

## 6. Порядок и зависимости

```text
1 Режимы single/double
2 Источник веса
3 Автоподстановка + водители + audit stubs
4 Площадка primary/spare  ──┐
5 Адаптеры терминалов     │  (параллельно после 4)
6 Годовая база / архив    │  (можно параллельно с 4–5)
7 Фото ◄──────────────────┘
8 ANPR ◄── 7 + anpr_mode из 4
9 Отчёты / аудит / docs / пароли
```

Этапы 1–3 и 6 дают рабочий контур **без камер** (базовая сборка).  
Этапы 4–5 готовят железо и протоколы.  
Этапы 7–8 — полная сборка после появления камер и успешного спайка ANPR.

## 8. Риски

| Риск | Митигация |
|------|-----------|
| Web Serial — один порт, только Chromium | Backend serial/TCP на этапе 5 |
| Ложный ANPR на повёрнутых камерах | `disabled_by_configuration` на spare |
| Нет автопроверки угла камеры | Эталоны + wizard оператора |
| Раздувание БД бинарниками | Файлы на диске, в БД пути |
| Миграция старых талонов | Nullable поля; default site + primary |
| ANPR < 50% на объекте | Функция выкл. по умолчанию; ручной ввод без изменений |
| `localStorage` Vite vs Flask | Рабочий контур — `127.0.0.1:5001` |

## 9. Definition of Done

1. Одиночное и двойное взвешивание; корректные источники веса; автоподстановка по номеру.
2. Площадка с основными и (опционально) резервными весами и общими камерами; явное переключение комплекта.
3. Терминал через адаптер или конфиг разбора; ручной ввод с фиксацией источника.
4. На резерве ANPR отключён конфигом; фото сохраняются.
5. Номер из ANPR / оператора / справочника → после подтверждения подставляются связанные поля.
6. Годовая база и архив с аудитом правок admin.
7. В талоне и отчётах видны площадка, весы, источники, снимки, режим, оператор, история изменений.
8. Базовая и полная сборки установщика; в полной — `video_enabled` без переустановки.
